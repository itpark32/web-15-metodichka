# 30. Мини-задачи для повторения

<p class="reading-time">Практика: 60-90 минут</p>

Выполняйте задачи без копирования готового решения. Сначала сформулируйте входные данные, результат и граничные случаи.

## HTML и CSS

- Сверстайте карточку события: дата, заголовок, место, описание и кнопка регистрации. Используйте семантические элементы.
- Добавьте к странице расписание в таблице с `caption`, заголовками строк и колонок, а также видео с субтитрами и SVG-иконку.
- Соберите сетку `2 + 1`: большая карточка занимает две колонки, две маленькие стоят справа. На мобильном экране порядок чтения должен быть естественным.
- Создайте форму входа с `label`, проверкой email, подсказками ошибок и видимым фокусом.
- Оформите промоблок с локальным шрифтом, градиентом и декоративным фоном. Проверьте контраст и поведение длинного текста.
- Добавьте переход состояния кнопки и анимацию появления карточек. Для `prefers-reduced-motion` уберите необязательное движение.
- Перепишите блок старого проекта по БЭМ и вынесите повторяющиеся значения в SCSS.

## Макет и проверка

- Выберите экран в Figma, выпишите контейнер, сетку, отступы, типографику и состояния до начала верстки.
- Сравните результат с макетом наложением при одинаковом размере viewport. Исправьте три причины расхождения, а не отдельные случайные пиксели.

## JavaScript

- Получите из массива товаров только доступные позиции, увеличьте цену каждой на налог и посчитайте итог.
- Напишите функцию подсчета частоты символов в строке. Пробелы не учитывайте, регистр игнорируйте.
- Реализуйте линейный поиск объекта по `id`. Верните `null`, если объект не найден.
- Напишите валидатор имени, email и возраста. Ошибка каждого поля должна отображаться рядом с ним.
- Рассчитайте итог заказа в копейках, округлите скидку по заданному правилу и обработайте нечисловой ввод.
- Найдите ошибку в незнакомой функции с помощью breakpoint, Scope и Call Stack. Запишите гипотезу и доказательство причины.
- Выбросьте `Error` для некорректных данных заказа, обработайте ожидаемую ошибку на границе интерфейса и не скрывайте остальные ошибки.

## DOM и события

- Сделайте список задач: добавление, отметка выполнения, удаление. Используйте один обработчик на контейнере списка.
- Создайте модальное окно, которое открывается кнопкой, закрывается по Escape и возвращает фокус на кнопку открытия.
- Дополните слайдер счетчиком и отключайте недоступную кнопку на первом и последнем слайде.

## Асинхронность

- Загрузите пользователей через Fetch API и покажите загрузку, данные, пустой результат и ошибку.
- Сделайте кнопку «Повторить» после ошибки.
- Объясните порядок вывода для кода с `console.log`, `setTimeout` и `Promise.resolve().then(...)`, затем проверьте себя в консоли.

## Браузер, сеть и архитектура

- Проследите загрузку знакомого сайта во вкладке Network: найдите HTML, CSS, JavaScript и один запрос данных, объясните их статусы.
- Сохраните тему интерфейса в `localStorage`, временный черновик формы в `sessionStorage` и корректно обработайте отсутствие или повреждение данных.
- Спроектируйте REST-маршруты для списка задач. Для одного запроса покажите метод, URL, тело, успешный статус и ошибку.
- Разделите небольшой каталог на ES-модули: API, состояние, отображение и точка входа. Объясните, почему зависимости направлены именно так.
- Реализуйте два экрана без перезагрузки, меняйте URL через History API и поддержите кнопки Назад и Вперед.

## Критерий готовности

- код работает на обычном и граничном сценарии;
- имена объясняют назначение;
- ошибка пользователя не ломает страницу;
- в консоли нет случайных ошибок;
- вы можете объяснить решение без чтения кода построчно.
